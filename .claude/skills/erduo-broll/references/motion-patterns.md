# Motion patterns

这三种机制是按语义选动作的参考，不是固定版式。先用照片、真实 UI、图表、文件、人物或文字把对象说清楚，再让动作完成信息变化。配色、材质、元素数量和构图都由当前内容决定；不要把某次样片的绿色纸片复制成全片模板。

## 1. 拥挤压迫 → 收束交接

**适用：** 收藏越多越难找、信息过载、入口被遮挡、任务卡住。**不适用：** 信息已经分好类，或只是逐条讲清单。

- **动作因果：** 先让目标可辨认；新资料从不同方向进入并逐步遮断目标，密度成为问题；一个仍未解决的收束物接住资料，或把焦点交给下一镜。收束物不能提前呈现“已经整理好”。
- **前后景：** 背景给稳定空间；中景承载不断增加的来源；前景只留目标、状态或交接物。照片、网页、聊天记录和纸页应保持各自形态与重量，不统一变成等宽卡片。
- **阅读停稳：** 压迫阶段要持续到观众确认困境；收束完成后留一段静稳，让人看见“问题仍在”。不要在前半镜头就给出整洁答案。
- **跨镜继承：** 末帧的文件夹、搜索框、选中对象或焦点标记，原位成为下一镜起态。镜头可换景别，但不要先清空再重建。

## 2. 一簇资料 → 分类分流 → 分层落定

**适用：** 同一堆材料需要被区分为来源、观点、例子或其他具名类别。**不适用：** 类别之间没有真实差异，或重点是比较高低而非归类。

- **动作因果：** 先展示可辨认的资料簇；焦点依次选中对象，对象再移动到具名去向；对象落定后，标签或关系线才出现。每次移动都回答“谁因为什么去了哪里”。
- **前后景：** 起态允许叠压，但至少看得出材料不同；分流时只让当前对象位于最高视觉层；终态用尺寸、形状、裁切、景深或纵深区分类别，不必排成三个等宽栏。
- **阅读停稳：** 主关系线与类别名在缩小观看时仍应先被看见，辅助字可以更少。全部落定后停止搬运，保护结论和关键短句的阅读时间。
- **跨镜继承：** 保留一件已选资料、同一个焦点标记或一条已建立的主关系，让下一镜从“已分类”继续生成关联或提纲。

SVG 可用于清楚的关系、路径、真实数据图表、遮罩和已获许可图标。路径应连接已落定的端点，线宽、明度和标签需在成片尺寸可读；不要用抽象 SVG 代替尚未取得的真实产品、人物或证据。

## 3. 路径抵达 → 焦点推进 → 内容成形

**适用：** 流程推进、线索汇合、从证据生成提纲、从路线抵达结果。**不适用：** 两个静态方案的并列比较，或没有先后因果的素材陈列。

- **动作因果：** 路径先建立方向；焦点沿路径推进并在关键节点短停；抵达触发节点展开、段落写出、图表聚焦或照片被定位；新内容成形后接管焦点，路径与工具退到次级。
- **前后景：** 背景路径负责方向，中景节点负责进度，前景只放当前焦点和正在生成的内容。焦点未抵达前，不要让终点自己完成动画。
- **阅读停稳：** 抵达不是结束。最后一次动作应是内容落定、工具退让，并给成形结果最长的稳定阅读区间。
- **跨镜继承：** 把终点内容、焦点位置或运动方向交给下一镜；若下一镜转向思考，让路径淡出而内容留在原位扩展。

## 实现约束

1. 先写清对象的起态、触发动作、终态和可读停稳，再写时间线。
2. 空间移动优先用 `x`、`y`、`scale`、`rotation` 和 `opacity`；入口、持续移动、落定微动若会争用同一 transform，拆到不同 wrapper。
3. 使用一条 `paused` 且可 seek 的时间线；初始隐藏或位移在 CSS 或同步 `gsap.set()` 中立即建立，不要靠时间线 `t=0` 才修正首帧。
4. 示例与实际镜头使用项目已准备好的 `assets/NotoSansSC.ttf` 和 `assets/gsap.min.js`。字体与 GSAP 不复制进发行仓库，也不在运行时联网获取。
5. 技术检查证明可渲染和停稳；最终仍需观看联系表与动态预览，修正看不清、动作无因果、层次互抢或跨镜断开的地方。
