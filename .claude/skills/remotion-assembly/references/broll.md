## 适用时机

装配流程两处必读：
1. **划章节之后、产出装配方案表之前**——编制素材清单（规则 2），清单结果写进方案表的「素材缺口」列。
2. **写每个证据段 / 案例段的代码之前**——为该段选素材呈现档位（规则 3-6），判断是否升级接管、是否需要 punch-in、缺料走哪条兜底。

## 0. [总纲] Remotion 是合成器，不是绘图板（2026-07-16 seg01 血泪定案）

「产品体验」类画面（打字、生成、界面、演示、操作流程）**一律用真素材剪辑**，手绘 CSS 复刻专业 motion 团队的作品必败——seg01 手绘三轮被否，换 Lovable 官方片 4.5 秒直接达到基准片质感。手绘只做 HUD 层（侧标/字幕/图表/印章/比喻图形），那是我们的主场，基准片也只手绘这层。
每段动工前先问：**这段基准片（参考对象）用的是真素材还是手绘 HUD？**素材段去采，HUD 段去画。

### 素材四级优先级（升级版，取代旧三级）

**① 自录产品屏**（最高：登录真实产品录操作流程，个性化、可控、与参考完全同源——基准片的「Let's build something, Isaak」就是自己账号录屏。需用户操作，装配前列入录屏清单：场景、时长 15-30s、1080p+、隐藏个人敏感信息）
**② 官方视频剪辑**（yt-dlp 采官方频道/官网片，剪 3-8s 直接当接管段底）
**③ 网页截图**（无头 Chrome 抓官网 1080p）
**④ UI 模拟卡**（最后兜底）

四级围绕「具体产品/案例」设计。**示意性素材**（不指向具体产品的观众侧演示，如「你录好的底板视频」）不入四级：可用通用实拍 footage（规则 9）、手绘示意件或标「素材缺口待供料」，不强行套四级采集义务。口播未点名具体平台/产品但操作真实存在的（如「租一台云主机」），同按示意性处理——**禁自选品牌**引入口播没有的具体产品；确需真素材时标素材缺口交用户裁定。

### 视频素材自采与剪辑管线（seg01 实战验证）

1. **搜**：`yt-dlp --print "%(channel)s | %(title)s | %(duration)ss | %(id)s" "ytsearch8:<产品名> official"`——认准官方频道名，第三方教程不要。
2. **下**：`yt-dlp -f "bv*[height<=1080][vcodec^=avc1]+ba[ext=m4a]/b[vcodec^=avc1]/b" -o "public/broll/<名>.mp4" <url>`（`[vcodec^=avc1]` 过滤见 2c 铁律：默认高清常是 AV1，与 HEVC 同罪不入库）。遇 403 依次试：加浏览器 UA、`--cookies-from-browser`、走代理（基准片雷区：yt-dlp 403 / fetch 不走代理 / Firefox cookie）。
2b. **验真**：任何下载/抓取的素材入库前跑 `file <文件>` 验格式——防盗链常返回 HTML 却存成 .png/.jpg（基准片雷区「PNG 实是 HTML」，直接采纳为固定步骤）；视频素材同时 `ffprobe` 验编码，HEVC 先转 H.264 再入库（防 Studio/渲染黑屏）；渲染前 `ls -lO public/footage public/broll` 查 **dataless** 标志——同步盘驱逐的空壳文件会让 bundle 永久卡死（错题 #25），驱逐件从原件恢复。
2c. **登记再生来源**：每件入库素材在 `public/assets/SOURCES.md` 补一行再生方式（命令/裁切参数/URL）——2026-07-16 同步盘驱逐事故后铁律，有清单 15 分钟全恢复，没清单就是灾难；用户原始录制件是唯一不可再生的，必须另存备份。yt-dlp 抓视频**必须加 `[vcodec^=avc1]` 过滤**（默认高清格式常是 AV1，与 HEVC 同罪不入库）。
3. **选段**：每 2s 抽帧拼目录表（fps=0.5 contact sheet），Read 逐帧找「与口播语义同步」的 3-8s 镜头段（如：输入→点击→生成→成品）。
4. **嵌**：Takeover 内嵌套 `<Sequence from={beat(x)}>` + `<OffthreadVideo muted startFrom={F(素材起点秒)}>`（muted 必加，人声在主轨）。
5. **调色统一**：素材段加轻调色融入正片（filter: brightness 0.9-0.92 / saturate 0.95，按正片明暗定），原色直出=贴片感。**接管段统一档 = `brightness(.92) saturate(.95)`**（seg06 录屏接管实测定档，全片接管底色同值对齐，勿逐段目测微调；错题 #18）。
6. **剪辑加工**：需要强调处做 punch-in（crop+scale 切关键区域）、挑帧、变速；不要整段原速平铺了事。**ffmpeg 裁剪素材必须重编码**（`-ss … -c:v libx264 -c:a aac`，禁 `-c copy`——起点无关键帧会片头冻帧，官方明文+基准片雷区「视频静帧」成因）；能不裁就用 `<OffthreadVideo startFrom>` / `<Video trimBefore>` 非破坏裁剪；含媒体的 Sequence 加 `premountFor={fps}` 防首帧卡顿——**但 `premountFor` 依赖 Sequence 默认 absolute-fill 包裹层来在预载期隐藏内容，同一 Sequence 禁设 `layout="none"`（去掉包裹层后 premount 失效 / 预载帧提前可见）；需要预载的媒体 Sequence 保留默认 layout，定位裁剪交给外层容器（overflow:hidden 固定尺寸卡）。外层若用 `return null` 手动门控容器可见性，null 开门时点必须比 enterAt 早 ≥premountFor 帧（seg06 实测：容器 `frame < enterAt-30 return null` 配内层 `premountFor={30}`），否则父级 null 会砍掉子 Sequence 的预载窗、premount 白做、首帧仍黑。** ffmpeg/ffprobe 可用内置版 `npx remotion ffmpeg`（换机免装）。
- 版权口径：官方宣传素材用于评论性视频，与基准片同尺度。

## 规则

### 0.5 [铁律级] B-roll 缺位不降质感（用户裁定 2026-07-24）

- **MG 本身必须独立成立**：参考片就算抽掉全部 B-roll，纯 MG（kicker 骨架+彩 hero+无框图表+清单+ghost）的质感也成立——素材缺位的段落按纯 MG 语法承载（specs §6.5 形态库），**禁把「没素材」当质感降级的借口**。
- 素材是加分项不是前提：有素材按四级优先级用；没素材时段落包装照常走满编 MG，不留空窗、不塞凑数模拟卡。

### 1. [铁律级] 真素材优先级实施细则

design-system 铁律 4（真素材为主体，组件只做包装）的素材层实施细则：
- 引用推文/帖子/文档用真截图装 ShotCard；没有截图的引用用 QuoteDoc 自绘同款；品牌一律真 logo（原 assembly SKILL「真素材优先」节，完整搬入于此）。
- 每个 CASE 段必须有至少 1 帧产品 UI 证据，优先级按上方四级。用黑底文字 chip / 抽象流程图代表一个具体产品，视为装配未完成。
- **粗剪自带真素材段（0724-01 新输入形态）**：用户可能把 B-roll（录屏/实拍）直接剪进粗剪交付——素材接入抽帧检查（assembly §0.5）发现画面切走人物的段时：0.5s 步进细扫定精确边界 → 与 SRT 核对语义对齐（说到哪切到哪）→ 按真素材段处理：**MG 全让位**（仅侧标+字幕；素材多为亮底，侧标垫深色小底板保可读），不叠任何卡、不再采集。此形态视同①自录屏档，是最省事的一档——方案表里直接标「已嵌粗剪」。

### 2. [义务] 装配前素材清单：每案例 1 张产品截图或 5s 录屏（AI 优先自采，不等用户供料）

- 装配方案表定稿前，按脚本逐案例收集：**每个案例 1 张产品截图或 5s 录屏**；场景类案例（驾驶/办公/工厂）另备通用实拍 footage。
- **素材自采管线（2026-07-16 seg01 验证，优先级最高）**：凡是有公开官网/产品页的案例（Lovable/Jasper/Manus/Tesla…），用 Remotion 自带无头 Chrome 直接抓 1080p 真实页面，AI 自己动手不等供料：
  ```bash
  node_modules/.remotion/chrome-headless-shell/*/chrome-headless-shell*/chrome-headless-shell \
    --headless --disable-gpu --screenshot=public/assets/<名字>.png \
    --window-size=1920,1080 --hide-scrollbars --virtual-time-budget=10000 "https://目标页"
  ```
  抓完必须 Read 检查成图（有的站渲染失败/弹 cookie 墙）；需要登录态或滚动交互的页面才转由用户录屏。
- **附带 why（基准片手法破案）**：接管段的氛围底色取自被讲产品的品牌视觉（他开场的粉紫渐变=Lovable 品牌色）——抓到真页后，从页面取 2-3 个主色做接管段渐变底，氛围自然统一。
- 素材落盘：视频 mp4 放 `public/broll/`，截图放 `public/assets/`；仍缺的写进方案表交用户供料。
- **缺料兜底：UI 模拟卡**规格——白色圆角卡 + 输入框 + spinner 动画 + 生成文本逐行打出（interpolate 驱动逐行 opacity），参照基准片 Jasper 段「Generating Campaign Brief」卡。**模拟卡不上「模拟示意」标签（用户裁定 2026-07-24）**：合规靠内容——禁假 logo、禁自编真实数据、正文只排方案给定文本；「这是模拟」声明写在方案与代码注释里，不上屏打标签（0724-01 终审判丑删除）。

### 3. [基准] 真素材密度与三档用法

- 密度基准：约每分钟 1 次真素材段落、合计占片长 15% 左右（基准片 356s 约 6 段 50-60s；我们首片仅 2.5%，是主要差距源）。**单片标定声明**：此基准（含 rhythm 8 的 20-60s 包装点频率）由 356s 单一参考片测得；换题材档（教程类操作驱动、冷静拆账类慢语速）暂行沿用但须在章法 pass 复核，失真即重标定，勿当铁律硬套。
- 三档用法，按叙事权重升档：① 右区大卡（正文可读）→ ② punch-in 关键句特写（规则 5）→ ③ 全屏素材接管（规则 6）。引用/演示/B-roll 三类素材默认考虑接管档而非塞右区。

### 4. [判据] 素材卡最小宽度与升级 takeover 的判断标准

- 右区素材卡最小宽度 **660px**（右区 x1150-1848 共 698px，基本吃满）。
- 可读性判据：**正文关键句在 1080p 下不小于 16px**（整卡准入底线档，字高三档见 specs.md §2）。按 660px 宽仍达不到时，二选一：裁切只放关键句区域，或升级为 A 级素材接管（接管态素材卡宽 ≥1100px、居中偏右）。**禁止为塞进右区整体缩小**。

### 5. [节奏] 引用类素材必走 punch-in 二段式

推文/文章/文档类素材按两拍出场：
- **stage1**：完整全卡 2-3s，立真实性。
- **stage2**：punch-in 切到关键句特写——关键句字高 **≥40px**、荧光高亮、黑底中文译条贴在该行正下方，与口播同步。
- **punch-in 实现 = 卡框不动、卡内内容动画变焦**（seg03 词级读帧修正，用户过审）：容器 overflow hidden，内容 scale 1→1.5-1.7、origin 对准关键区、~0.5s ease 完成——基准片 z17 中间帧证明是动画变焦不是硬切（旧表述「两 stage 硬切」作废）。高亮/译条必须放进变焦组内随卡同变换，否则穿帮。ShotCard 已内建 `punch` prop。
- **高亮是口播的光标，一卡可多轮**：载体干净进场（禁止把高亮/标注预先烤进素材图），念到哪句刷哪句——论点句刷论点段+译条，背书句刷背书评语+小译条（seg03 一卡两轮实测）。每轮高亮左→右扫入 0.4s，译条贴所译句下沿、避开卡内头像列。ShotCard `highlights`/`zhBars` 分拍数组。
- **stage3 复位/退场义务（0715-02 S04 打回沉淀）**：punch-in 不是终态——关键句讲完后必须二选一：内容 scale 回 1 复位（~0.5s ease，高亮/译条同步熄灭），或整卡退场；**禁止带着 1.5-1.7 倍变焦态停留进后续拍**（后续拍构图失衡、卡内截断穿帮）。验收判据：卡 exitAt 前若仍处变焦态即算未复位违规。

### 6. [义务] 每个 case study 至少一段 8-15s A 级素材接管

- 每个 case study 选叙事峰值处做一段 **8-15s** 全屏素材接管（录屏/实拍/白底产品段），素材卡宽 ≥1100px。
- **与 2026-07-20 接管降级的衔接**：该裁定降的是「每 60-90s ≥1 次」全片频次指标，不豁免本条——case study 峰值素材正是 layout §2「默认接管翻转·终审裁定」明列的「真正必要场景」，本义务照旧生效（快闪列举豁免见上方触发界定）。
- **接管期间 HUD 双线叙事（2026-07-21 基准片 B-roll 片实证）**：左带不只「留守」——可挂步骤/要点 chip 栈**跟口播逐项点亮**（实证 60s：SCENE 02 侧标 + 「有意思的文章→自动提炼要点」chip 栈随讲随亮），素材演示与 HUD 论点双线并行，接管段不再是素材独角戏。
- **接管构图选档**：全屏还是偏置（素材 70-75%+左带叙事带）还是半屏人物共存，按 layout 规则 2.5「素材排版三档」判——竖向/长条内容选偏置档，口播主导素材配图选共存档。
- **case study 触发界定（2026-07-18 泛化压测定）**：单案例口播 ≥15s 且有独立叙事弧 = case study，本条与 R2 义务生效；单项 <8s 的多案例连发 = 快闪列举（selection.md #10），义务降级为「整组一帧代表性 UI 或纯 HUD」，禁按 case 逐个硬凑接管。**8-15s 是素材接管档的设计窗不是普适下限**：口播句窗不足时走收窗+提前叠化（下条）或降为 2-4s 整屏插拍档（rhythm 规则 2），不为凑 8s 拖素材。
- **接管人物整段退场、不带 PiP**（用户否决清单 ②：Takeover 一律不带小窗；报告「人物完全退场」与修改单-04 裁决 3「PiP 或退场」两说均被此否决取代，以代码 Takeover `pip` 默认 false 为准）；左区章节 HUD 留守；三区禁入约束只管人物在画时的叠加元素。z 序、接管频次（2026-07-20 起为可选、非硬指标）、升格机制（靠字号提级+清场+红绿镜像框，非压暗）见 layout（边界节）。
- **接管窗长度贴合素材自然时长、优先自然速率**（seg06 实测裁定）：素材短于预设窗时，先「收窗 + 提前叠化退场」把窗口收到素材长度，**不要为填满预设窗而 `playbackRate<1` 慢放**；`playbackRate<1` 慢放仅在「界面滚动类且窗口不可收窄」时作末选，且系数不低于约 0.7（更低界面动作会「假」）。seg06 Manus demo 10.5s 素材 → 弃 mini 方案初拟的 0.72 慢放、改收窗至素材长 + 提前叠化。
- **退管手法（seg05 §七 帧级校验沉淀）**：接管结束 = 接管 MG 组压实拍渐隐 ≈1s 整组全清，退后左区不留接管内容残留；「缩小 HUD 化留左侧」与帧证据不符，禁用。

### 7. [义务] 产品「怎么工作」的口播必须配录屏 + 打字机进度译条

- 凡口播在描述某产品「会做什么/怎么工作」，必须配真实录屏而非抽象流程图；录屏底部挂半透明打字机字幕条，实时翻译屏内动作，逐句对齐口播描述（基准片 Manus 段：『first unzipping the file』『then browsing each resume page by page』）。
- **与规则 6 的裁决（2026-07-18 回归补）**：快闪列举/多步骤连发段（单项 <8s），本条整段录屏义务降为「整组一帧代表性 UI 或 2-4s 整屏插拍」；全程录屏+译条只在 case study 档（≥15s 独立叙事弧）强制。

### 8. [义务] 法规/财报/论文引用必须上原文截图并高亮被引句

- 截原文首页或关键条款成图，白底文档卡呈现（圆角+阴影+被引条款荧光高亮+白话译条），放右区或接管段；带年份/文号信息保留（证据感来源）。
- 黑底 chip 只能做原文旁边的摘要标签，**不能替代原文**——转述与证据差一个说服力档位。

### 8.5. [规则] 遮罩揭示法：烧入高亮/译条的素材图无干净帧时的动态化标准解

- 适用：引用素材（新闻卡/政策公告/推文）只有「高亮+译条已烧入画面」的帧、拿不到干净底图时（无法程序化分拍刷高亮，见规则 5）。**禁止**用像素修复抠掉烧入高亮（会留花斑）。
- 做法：用一层**白色（或页面底色）遮罩盖住烧入的高亮区**，播放到对应口播句时 `mask scaleX 1→0` 从左起揭开（~0.4-0.5s ease），把既有烧入高亮当「动态刷入」用——效果等价规则 5 的高亮光标，只是刷的是既有烧入而非新绘。遮罩 `transformOrigin` 对准该行左缘，且必须放进卡内 punch-in 变焦组随卡同变换（同规则 5，否则穿帮）。
- 两用实证（换素材沿用）：S05 news 卡（`news-jasper-burned.jpg`，基准片 68s 帧、65s 无干净帧）+ S12 政策卡（`policy-doc-zhu.jpg`，《数据出境安全评估办法》首段黄高亮已烧入）。**登记制度**：两件均已在 `public/assets/SOURCES.md` 登记「配遮罩揭示法」再生说明；凡入库的烧入高亮/译条素材，必须在 SOURCES.md 同步登记此标记（无干净帧的引用件按此核对，避免下游误当可程序化分拍处理）。
- 组件化评估：跨片高频后抽 `MaskReveal` 组件（承 D2；截至沉淀日仍内联）。

### 8.6. [规则] 转述引用降级路径：没有原文可截的「人说的话」

- 适用：访谈转述、内幕消息、口头共识（「朋友跟我说」「内部共识」）——既没有推文/文章可截（规则 8 不适用），也不是产品段（规则 10 假产品兜底不适用）。
- 做法：**名牌 + QuoteDoc 自绘引用卡**——这是唯一允许自绘引用载体的场景。名牌可匿名化（「某大厂模型团队 · 内部人士」+ 通用头像位），引用卡必须带**信源标注行**（信源身份 + 时间 + 可信度口径如「转述」「未证实」），禁止做成和真截图同观感的伪证据。
- 严禁：黑 chip 顶替引用内容（规则 8 同款禁令）；给转述内容伪造平台 UI（伪推文卡=假证据）。
- 出身：2026-07-18 泛化压测（访谈转述类内容两头落空）。

### 9. [规则] 场景化铺底：口播描绘场景时，整屏场景素材铺底 + MG 叠加叙事（2026-07-21 对照基准片 B-roll 片扩写）

- **触发判据**：口播在**描绘一个场景/画面**而非陈述论点或出示证据时（「两个小时的全英文发布会」→ 发布会人群场景；驾驶/办公/工厂同理）；hook 与 BEFORE/AFTER 对比章高发。
- **素材来源两路**：① 实拍库存 footage；② **AI 文生视频生成场景**（基准片实证：豆包 B-roll 片 4s 发布会人群场景带「豆包AI生成」水印——情绪场景素材他就是生成的，不是实拍库存）。生成素材入库照走 SOURCES.md 登记并标「AI 生成」，按平台要求保留/添加生成标注。
- **红线：AI 生成仅限情绪/场景/示意类**。证据类素材（产品录屏、新闻、截图、数据图、用户评论）**禁止 AI 生成**——那是伪造证据，一票否。
- **MG-on-footage 版式**：整屏铺底时人物区禁入约束失效，MG 仍靠左成栈——左上章标 kicker（BEFORE/AFTER 式）+ 左侧数据/步骤栈**逐行跟口播点亮**；左缘暗渐变/scrim 保 HUD 可读；字幕位不变。实拍供场景感、MG 供论点，同帧双线叙事。
- 纯色底不硬扛超过 30s 无视觉换气。

### 9.5 [流程] 占位素材制：素材缺口不阻塞装配（2026-07-21 定）

- 用户供料慢/录制成本高时，先用**占位素材**（参考片截取、库存近似件、低保真生成件）把排版/节奏/语法全部跑通——素材是文件引用，真素材到位后同名替换重渲即可，代码零改动。
- **红线**：占位素材必须在素材目录 MANIFEST 与方案表双标「占位待换」；**发布前必须逐段替换**——参考片截取件含他人账号/内容/版权，进发布版=抄袭。终审交付页须向用户明示哪些段仍是占位。
- 占位件烧有原片 MG/字幕时可卡内裁切取内容区；音轨一律剥离。

### 10. [兜底] 查无素材的历史段落：造品牌白底假产品段，不降级文字卡

- 案例找不到任何录屏/截图时，用品牌色+仿产品 UI 造一段浅底全屏序列（BrandTakeover 模板）：浅色底（用 SURFACE.light 档）+ 品牌 logo 入场 + 仿产品 UI（输入框/加载条/生成动画）+ 大数字 kinetic type，整段 8-12s。
- 浅底段同时承担章节视觉换气功能（与全片暗调形成反差）。

### 12. [铁律级] 素材段嵌入写法与渲后验收闸（2026-07-21 0721-01 六段坏卡定案，错题 #34）

- **嵌入写法**：OffthreadVideo 卡内裁切一律用「video 100% 铺卡 + transform scale 过冲」（0721-01 七个素材段中唯一渲染正确的 S14 写法）；**禁用「超大盒 style width + objectFit/translate」**——渲染端 width 不生效，内容按卡宽渲染再被位移截断，成片黑条/竖条/空卡（S02/S06/S07/S10/S13/S16 六段中招，S16 空玻璃当时还被误诊为「占位素材偏浅」）。
- **渲后验收闸（每个素材段渲后必跑，AI 自审不得跳过）**：抽卡内帧三查——① 卡内四边铺满、死区 ≤5%；② 原片字幕/窗口 chrome 零残留；③ 稳态不透明度 =1。startFrom 落点加抽 +0.3/+0.6s 防源内硬切。**抽帧点必须落在素材在场窗口内**（0721-01 教训：S13 素材 6.5s 退场后接自绘结果卡，抽帧抽在结果卡上→85% 纯黑的素材窗漏检；交付时自称「全部渲帧审过」但抽帧点全避开卡内部）。**已脚本化**：`node scripts/qc-master.mjs <mp4> [时长] [硬切白名单] [素材段时间表]` 自动抽帧+冻帧/编码断言（素材段冻帧=WARN、人物段冻帧=FAIL、B 帧/非 faststart=FAIL），图像三查仍看抽出的帧。
