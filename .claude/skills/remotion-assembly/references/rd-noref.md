# 研发模式-B：无参考片的新编排设计（rd-noref）

> 定位：selection.md §C 出口的唯一承接。语法库无对应编排 **且** 无参考片可抽帧时走此流程——替代研发模式-A（§2.5 密集读参考帧）的方法本体。
> 原则：**新编排 = 旧语法的新组合 + 受约束的最小新造**，不是自由创作。新造部分必须服从全部硬约束（三区版式 layout 1 / 纵向占位表 layout 10.5 / 退场纪律 rhythm 4 / 峰值拍 rhythm 2 + 宏观节奏 rhythm 8 / 动效词汇 motion 三档 / 亮面禁裸字）。
> 出身：2026-07-18 泛化压测三案一致暴露「语法缺口+无参考=方法真空，只能自由发挥靠终审兜底」后建。

## 第 0 步：先判要不要找参考（辅路由，限时）

该编排若大概率有成熟外部先例（榜单揭榜、图表解读、横评矩阵这类通用形态），可先走 `mine-video-reference` skill 挖参考片。合格标准三条：同信息密度档、口播驱动、可抽帧对齐。**挖到 → 转研发模式-A 正常走**；24 小时内挖不到合格参考 → 立即转下面三步，禁止无限找参考。

## 三步方法（替代「读参考帧」）

**作业域按缺口大小收窄**（2026-07-18 回归补）：缺口只有一拍时，三步法作用于该拍——方案 = 该拍 2 个互异关键帧方案，judge 只审该拍并回看前后拍衔接，不必整段重排；单意象小缺口（<8s 非主拍）不进本流程，走 selection §C beat 级轻量口径。

### 1. 多方案生成

同一段由 agent 产出 **2-3 个互异 beat 方案**，每方案：
- 逐 beat 声明所引语法条目（selection.md 指针格式）；新造部分单独标注 + 一句设计理由。
- **强制差异声明**：方案间至少一项结构性不同（主区选择 / 峰值形态 / 组件族），防止退化成三个近似方案。
- 每方案渲出关键拍静帧（render-service stills，3-5 帧/方案）。

### 2. judge panel 择优

起独立 judge（mg-judge，不带方案作者上下文），输入 = **各方案渲染帧 + 该段 SRT**（不给方案文字自述，防自证）。按 rubric.md 四维 + rhythm 审计五条 + layout 验收清单打分，输出结构化评分与择优理由；可从落选方案嫁接单点优点。

### 3. 用户过目定稿

择优方案（±嫁接）渲段成片交用户裁定——用户终审是本流程不可自动化的固定闸（与构图裁定同级）。过审后：
- 新编排按现行沉淀流程写回对应板块真源（narrative/rhythm/infographic 对应节）；
- selection.md §A 加一行（或并入同类行）；新组件规格入 specs.md、组件从 R11 待建清单销号；
- **语法库随片增长**：下一片同句型直接查表命中，不再进本流程。

## 验收红线（与研发模式-A 相同）

三道闸不变：QC 探针零违规 → mg-judge 四维 ≥7 → 用户终审。新造组件禁裸 div（selection.md §C）；SFX 按 A-G 查表，新事件位查无对应时按「音色成套」原则就近归族并在音效设计谱记一笔，禁自选新音源。
