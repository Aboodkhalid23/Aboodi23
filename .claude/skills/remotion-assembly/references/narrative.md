# 章节叙事包装

> 目录：1 五节点总纲 · 1.5 数字重锤四件套 · 1.6 引用段名牌+背书链 · 2 hook 密度 · 3 hook 大数字 · 4 印章判词 · 5 VS 决算场 · 6 全片级判词 · 7 新概念 lockup · 8 CTA 徽章 · 9 章节判词徽章 · 10 侧标骨架 · 11 分页式 · 12 案例页

## 适用时机

装配流程第 2 步「分段方案」阶段读：拿到 SRT 后划分章节、指定每章包装点时，用本文件决定叙事骨架（侧标/分页/案例页）与五个能量节点（hook、重锤判词、阵营决算、全片级判词、CTA）的规格。写装配方案前必须先把这五个节点在时间轴上标出来。

## 规则

### 1. 叙事能量分配总纲：五节点必须改变视觉规格

- 全片规格不能从头平到尾。hook、重锤判词、阵营决算（VS）、全片级判词、结尾 CTA 这五个节点必须突然改变视觉规格（放大、居中、清场、换版式），让观众感到「这句话不一样」。
- 反例：v3 全程用同一套左区 h2 + 白板印章，重锤时刻与普通信息点观感无差。
- **短片档（≤60s，0724-01 沉淀）**：五节点按语义有则用之、无则不硬造——教程/排障类短片常无 VS 决算与全片级判词（0724-01 两者皆 0、Stamp 0，judge 零打回过审）；hook 与 CTA 仍必备，章级判定/概念 lockup/警示拍可充当中段能量节点。段数按时长等比缩（45s ≈ 7-8 段）。

### 1.5 数字重锤四件套（seg02 过审沉淀）

- hook/论点段的核心统计数字用「四件套」同拍呈现：① mega 级滚动数字（滚 1.5-2s、有起点悬念如 38→73）② 同步点亮的可数图形（waffle/点阵，进度跟随滚动）③ 原文证据同步高亮 + 译条贴句下 ④ 来源信息（kicker 或来源条）。四样都指向同一个数字，重锤才成立。
- 滚完即止：**落定不配重击**（音效同理，A-G 语法 C 条＝数字滚动 rise 铺满滚动期、落定不加击——A-G 配声对号表在 `remotion-sfx` SKILL §4 与 references/audio.md 规则 8）；「压暗」一项已被用户否决，升格靠字号与清场。
- 反面：单独一个数字 0.87s 滚完 + 预烤译条提前剧透 = 重锤哑火（seg02 v4 教训）。

### 1.6 引用段：名牌先行 + 背书证据链三件套（seg03 过审沉淀）

- **名牌 ≠ lockup，是两个独立节拍**：引用类段落先单拍出名牌（头像+平台徽章角标+姓名+身份，答「谁在说」），引用内容 lockup 跟着口播逐拍出（引号+主语行→动词重锤）。反面：整块 lockup 连判词一次性全亮 = 重锤提前 5.4s 剧透（seg03 原版病根）。
- **重锤动词允许压句头提前 ≤0.5s**（基准片 CRUSHED 比「碾压」出口早约 1s 压句尾抢半拍），但禁止提前一句以上。
- **数字不够重锤档就降级为徽章计数**：传播量/背书类数字（如 2000 万浏览）重心是权威感不是冲击力，不上 BigNumber 四件套，改用「背书证据链三件套」——① 金色计数徽章（滚动数字挂证据行）② 人物背书徽章（头像+认证勾，比纯文本 chip 权威一档）③ punch-in 特写怼向被背书的关键句。**punch-in 服务语义不服务数字**：镜头怼的是「谁认同」（Seems to be accurate），数字交给旁边的小徽章。

### 2. hook 段（前 10s）密度拉满 [sev5]

- hook 段必须有 SIZE.h1 级主视觉，且左右区同时有内容在动；禁止只挂一张小窗口卡开场。
- hook 段元素密度不得低于正片最密段落；8 秒内左区至少完成两次信息替换（如逐字机打 HeroText 问句对仗）。
- 基准片打法：全屏级画面（打字大字、字高约占画面 1/4）+ 产品录屏 + 人物 PiP，第 2 秒即有视觉冲击（PiP 为原片手法描述，我们不复刻——已否决，见 layout.md §3）。

### 3. hook 核心数据必须做成重锤大数字 [sev4]

- 逐字稿里承担 hook 功能的核心统计数字，必须用 BigNumber（SIZE.h1 以上量级、语义色）呈现，禁止只用 chip 带过。
- 必须配可数化图形翻译数量感：点阵逐格点亮（MatrixIcon 扩展）、波形等；信源截图卡（ShotCard）保留在另一区作证据。
- 反例：v3 的「73% 套壳」只给一枚 chip，字号不到参考片 1/6，而 BigNumber 组件片尾 ¥0 已用过——是装配选择问题不是组件缺失。

### 4. 重锤 = 印章：判词的载体与锚定 [sev5]

- 结论性判词用 Stamp 盖章（被吸收/被蒸馏/无可替代/溶不掉），每章至多一个；红章判死、绿章免死。
- **阵营色视角归属**：红/绿相对**被判对象**而定（被判死=红、幸存/免死=绿），不相对叙事主角——「X 把 Y 打懵」里红属 Y。**双正分支**（A 人群选 X / B 人群选 Y，无判死语义）禁套红绿 VS 与 Stamp，用中性双列 + Formula/recap 载体。
- Stamp 必须锚定在被判对象旁：左区被判概念的下方，或右区卡片角上；禁止裸盖白板。重锤感靠位置 + SFX，不靠尺寸（裁决 1）。
- 同一判词禁止 chip 与 Stamp 同屏重复——只允许一种载体，出现重复时删 chip 留 Stamp（裁决 1）。**扩展为「一信息一载体」（用户裁定 2026-07-24）**：不限判词——正文/主载体已表达的计数或数字（如终端行 attempt N/5）禁再加角标徽章（×5）重复强调，装饰性重复徽章一律删（0724-01 终审判丑）。
- Stamp 视觉规格取既定值、装配时不自定数值：主行 fontSize 默认 48、章级重锤上限 64、整体宽 ≤360（裁决 1，specs.md §3 有同值）；底板/描边/旋转/英文副标等细则见 remotion-design-system references/texture.md 规则 3。

### 5. 红绿阵营必须收拢成「VS 决算场」 [sev5]

- 凡是建立过 A/B 阵营（红绿对仗）的片子，必须安排一个决算场让两阵营同屏对峙收拢，且出现在观众被要求做选择的那句话上。
- **决算场版式（seg17-mini 过审定型，取代旧「B 级压暗 + 满宽跨人物框」版）**：不压暗（压暗已被用户否决，见 layout.md §2），升格靠版式本身——
  - **侧区框而非满宽跨人物框**：红/绿阵营框各约 400×170、留在左右侧区、**人物区留空**（满宽跨人物版会压脸，一票否）；省略中心 VS 圆徽（它正落在人物区）。
  - **空框先立再填**：先把两只空框立起来制造「你站哪边」的悬置，再填内容。
  - **chip 分批入框对齐口播**：红框、绿框 chips 分两批入场，对齐「前三种/后三种」这类口播节点（红先满、绿后满），不一次性全填。
  - **红绿框 Breathe 相位错开**（如 0/30 帧），避免两框同步呼吸像一个整体；进场配一记重 SFX。问句大字用 SIZE.h1 放顶部。
- 反例：v3 的「只问自己一句话」只放了 kicker + h2 + 一张红卡，绿方缺席，六章红绿铺垫没有兑现。

### 6. 全片级判词升格规格：一部片限 1 次 [sev4]

- **单段/增量作业记账口径（2026-07-18 回归补）**：全片级配额（本条限 1 + Stamp 重锤 ≤2/片）在 segments.md 段登记表记账；单段方案拿不准档位时先按章级规格出、标「待全片账本核」，禁自行升全片级。
- 每部片指定唯一一句「全片级判词」（最终答案），用升格规格呈现：字号提级到 SIZE.h1 + 全屏清场（上一段元素先退）+ 左区两行式大字（关键词语义色）+ 符号化元素（≠、红色下划线等）+ 右区镜像大型图形符号呼应 + 重音 SFX 进场；不压暗（升格靠字号与清场，见 layout.md §2）。
- 该规格全片只允许出现一次，与普通章节 hero 拉开量级；出现两次即失效。
- 反例：v3 最终结论「头部护城河 绝不由 AI 建立」是一行普通 h2，与几十条 HeroText 规格相同，观众无法感知这是答案。

### 7. 新概念命名用单一 lockup，一次呈现 [sev4]

- 新概念命名（如「万能溶剂」）必须收拢为单一 lockup：语义色图标 + EN kicker + SIZE.h1 大字 + 副标，一次进场，让观众明确「一个新概念诞生了」。
- 禁止把同一概念拆散到左右两区分头出现；右区（白板/亮背景）禁止无底板裸文字，呼应元素只能用带 SURFACE 底板的卡片或图形。

### 8. CTA 徽章规格：语义色 + 图标 + 具体指令 + 前幕清场 [sev4]

- CTA 四件套（点赞/关注/收藏/评论）用 BadgeCard 式徽章逐个 stagger 进场，各带 lucide 图标与语义色描边（点赞 COLOR.blue / 关注 COLOR.red / 收藏 COLOR.yellow / 评论 COLOR.green），配 SFX。
- **布局形态（seg19-mini 过审定型）**：四件套 + 名牌**沿底部一条横排**排布（不是左区竖排堆叠）；**名牌先落定当锚点、约 3 拍后再逐个弹徽章**（先立锚再挂件，不同拍全出）；**评论徽章置末位且做成最宽**一枚 = 强调互动。片尾是全片唯一允许横排略越 x1150 侵入人物区的例外（人物已退场时适用；2026-07-20 复核：片尾默认人物在场不切黑，见 layout §2「片尾不黑」——本例外仅在确有素材接管收尾时生效）。
- ~~至少一个徽章给出具体可执行指令~~ **修订（用户终审裁定 2026-07-24，0724-01）**：评论宽徽章（具体指令文案）**可选非必备**——用户判「太丑」删除后仅点赞/收藏/关注三枚过审；「至少一徽章带具体指令」「评论徽章末位最宽」同步降为可选，用不用看片长与口播是否点到评论动作。
- 加频道头像名牌（头像 + 名号 + 下期见）。**名牌默认带真人头像（2026-07-24 起标配）**：全局资产 `public/assets/author-avatar.png`（形象照离线烘脸居中正方裁片，制法见错题 #40），`NamePlate` 传 `avatarSrc` + `avatarImgStyle` 满窗直贴（100%/left 0/top 0）；禁在小圆内用 CSS 旋转/偏移裁窗修歪。
- **收尾双形态（2026-07-24 增）**：① 徽章横排（本节既有规格）；② **单列纵向 lockup**（ segH 实测：眉标 THANKS FOR WATCHING→EN 小帽→中文大标 ≈72→带竖条的黄字签名行，一根轴线三级字阶收束）——lockup 档更收得住、适合口播只说「下期见」不点名四件套的片；口播逐个点名点赞/收藏/关注时用徽章横排。按片选一，禁混用。
- CTA 场开始前必须清空上一叙事段的全部残留元素（Stamp/图形提前约 1s 退场），禁止旧章印章挂着进 CTA。

### 9. 章节判词徽章内嵌章节卡，判决当句出现 [sev3]

- 每个阵营章节的判词徽章（描边胶囊：图标 + 判词，语义色）必须挂在章节 lockup 正下方，在逐字稿说出判词的那一句进场——判决与章节卡在时间和空间上都不许脱节。
- 章节结论可用底部公式条（如「AI 智力 ≠ 法律授权」）常驻到本章结束，把结论钉在画面上。
- 反例：v3 判决延迟约 20s 才以白板印章出现，与章节卡脱节。

### 10. 章节侧标是骨架

- 每章一换，编号递进营造推进感（`DISSOLVED · 01/02/03` vs `IMMUNE · 01/02/03`），红绿两阵营对仗；转场章用黄色。
- **中性片档（2026-07-18 泛化补）**：无红绿阵营的片型（横评/教程/复盘），编号递进照旧，配色用转场章黄或 ink 中性档，命名取章节主题词（如 `OPENAI · 01`、`搭建 · 01`）；禁强套判决词式命名。
- 组件：SideLabel，常驻层级与提层规则见 layout.md。

### 11. 分型/列举内容用「分页式」

- 不用 Checklist 一页堆完：每一型独立一章（MatrixIcon 矩阵图标 + 大字 + 英文 kicker + 补充 chip），信息密度低但推进感强。

### 12. 案例页固定结构

- 案例头（真 logo + `CASE 0N · 领域` kicker）→ 大数字（BigNumber 计数器）→ 事件卡（InfoCard：转折点）→ 后果 chips（红色，stagger）。
- 真素材优先：引用推文/帖子/文档用真截图 ShotCard，无截图用 QuoteDoc 自绘同款；品牌一律真 logo。
