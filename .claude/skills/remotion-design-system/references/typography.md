# 字体排印（Typography）

来源：assembly/0715-01/深度对比报告.md「字体排印」7 条 + 修改单-04 对抗审查后勘误·裁决 2。字号/颜色一律写 token 名，数值唯一真源是 `src/design/tokens.ts`（快照漂移过，禁抄数值）。

## 适用时机

装配流程中，分段方案定稿后、逐 Scene 写文字元素（HeroText / SideLabel / BigNumber / 各类带字组件）时读本文件；渲染前自检时按「规则 1」逐屏复核字号层级。

## 规则

### 1.（sev5·全片之首）每个信息屏必须有且只有一个「唯一最大字」

- 主导字字号 ≥ SIZE.h2，且 ≥ 同屏最小字的 3 倍；章节结论、冲击数字、全片级判词必须上 SIZE.h1 或 SIZE.mega，**h2 不算主导层**。
- 参考基准：基准片每屏必有一个 90-120px 级主导字，最大:最小 ≈ 4-5:1，辅助信息压到 kicker/subSmall 档；v3 全片 HeroText×10、BigNumber×3 全停在 h2，h1/mega 零次，Chip 用了 43 次，对比只有约 2:1，观感均质发灰。
- 核心比喻/全片关键词（如「万能溶解液」）禁止与 chip 同级出现。

### 2.（裁决 2·义务条款）章节 hero 一律用 SIZE.h1

- 「章节 hero 用 h1」是义务不是选项；h1 已按裁决提级（mega、h2 不变），数值以 tokens.ts 为准。
- 存量片子按此做全片 HeroText 主导层升级 pass（对应修改单 B16）。
- h2 降级为段内次要 hero；mega 档 HeroText 不支持（size 仅 'h1'|'h2'），冲击数字走 BigNumber。
- **章节标题两档制（seg04 过审细化）**：一个章有两类标题，别混用同一档——① **片名级 / 章结论级 hero**（全片主标题、章内结论句，如「AI应用死亡潮」单字 ≥100）走 SIZE.h1（=108）；② **章节常驻导航牌**（ROOT CAUSE 这类持续挂在侧标下的章内导航标题）用中文导航牌档（specs.md §3 实测约 **72**）白 900 + 下置 kicker 20 灰 tracked 0.3em，**常驻不 dim**，是介于 SideLabel title（44）与 h1 之间的独立小档、非 h1。旧对比报告把导航牌 72 误并入片名级 105 系口径（specs.md §3 已勘误）。像素真源见 specs.md §3，落 SIZE 阶梯时取 tokens.ts 最近档、勿硬造阶梯外字号（见规则 8）。

### 3.（sev3）Hero 大字默认三明治结构，回声行是标配不是可选

HeroText 组件已支持全部槽位，装配时按此用：

- **kicker**（上层，SIZE.kicker 档 tracked caps）：传 `{t, color?}[]` 分段数组做 EN 语义色 + CN 白双色同行；组件默认 kicker 先行入场（enterAt−10 帧），保留这个分拍，别把三层做成一次性贴上。
- **segments**（主行）：词级换色，一句只换一处色（铁律 3，见 SKILL.md）。
- **echo**（底层）：英文回声行（大写、宽字距、COLOR.grey），每个 hero 必填；可另加 **zhSub** 中文小字补充行。
- 参考：基准片「护城河 ≠ AI」三层结构；内部参考帧。

### 4.（sev4）章节开场一律用 SideLabel variant='title'，单行 label 只留给段内辅助

- title 变体 = 第一行中文白色 900 大标（可带 icon）+ 第二行语义色 tracked caps 英文 kicker，两层字号比约 2:1；组件已实现。
- 使用时机：每章开场的章节头必用 title；段内辅助提示、常驻小侧标才用默认 label。
- 反例：v3 把「CASE STUDY · AI 交易系统」挤成一行 kicker 档同色，没有标题感。证据：pair 45/65；内部参考帧。
- 裁决 3 已将 SideLabel 提升为顶层常驻（B17），提层细节归装配层，此处只管排印形态。

### 5.（sev4）亮背景（白板/白墙）上禁止无底裸文字

- 右区亮墙区域只允许自带 cardBg/scrim 的组件；确需裸字时垫 COLOR.cardBg 圆角 scrim。textShadow 不作为亮区可读性方案（实测压不住，接近不可读）。
- scrim 规格、SURFACE.light 变体、白板安全框等实施细则 → references/texture.md。

### 6.（sev2）数字卡说明行禁用「subSmall + greyDim」组合

- BigNumber 的 zhSub 说明行：字号高于 SIZE.subSmall 档、字重 700、颜色 COLOR.grey 起步（暗底）或 COLOR.white；enKicker 可随语义色。
- COLOR.greyDim 只允许用于卡片内部第三级信息，不允许承载「静态理论 · 价值归零」这类结论说明。
- 参考结构：基准片数字块 = 彩色竖线 kicker → 大数字 → 白色 bold 中文说明，说明行与数字同色系呼应。证据：pair 65 ¥0 块 vs 内部参考帧。

### 7.（sev2）分段换色文本必须保留段内空格，验收看渲染帧

- 混排规范：中英之间、中数之间、运算符（=、≠、→）两侧必须有对称空格。
- 陷阱：segment span 用 display:inline-block 时，尾随普通空格被 HTML 折叠——源码写 `{ t: 'Agent = ' }` 实际渲染成「Agent =万能溶解液」。根治方案是 segment 加 `whiteSpace:'pre'`（或空格替换为 ` `）；装配时确认目标组件已带此修复，否则自己垫 ` `。
- 验收以渲染帧为准，不以源码字符串为准。证据：pair 25；HeroText segment span（src/design/HeroText.tsx，segment 仍为 inline-block）+ scenes/Scene16.tsx「凌驾于AI」粘连注释（` ` 垫空格实证）。

### 7.5 彩色 hero 配方与行内关键词变色（2026-07-24 词级精读定档）

- **立体感真配方 = 扁平纯色重磅黑体 + 右下偏移 4-6px、blur≈8px 近黑软投影**。无描边、无挤出层、无多层叠字（segD 放大单字实证）——想要「高级立体」别加层，加一枚软投影就够。
- **行内关键词变色两式**：① 蓝系 hero 白=中性框架词、蓝=主题词高亮（「全是 **AI**」「就是**抄**」）；② 价值语义词**整词同色金**不做行内混色（纯人类原创/高价收购/$203M 同金）。一句只换一处色的铁律不变。
- **字数自适应宽度**：hero 落在固定左侧宽度带内，字越多字号越小（4 字 ≈150 / 5+ 字 87-116 @1080）；mega 数字同理走定宽自适应盒（specs §6.5）。落 SIZE 阶梯最近档，禁阶梯外字号（规则 8 不变）。
- **ghost 语义化**：灰不只是退场态——「大路货」类贬义词**生即为灰**（≈62% 白亮度）是刻意的语义用色；reveal 前的 ghost 预铺 10-50% 透明度，说到才提亮。

### 7.6 排版基本功四条（2026-07-25 用户点名「排版乱」后，100ha 屏原分辨率实测）

用户判词：我们的屏「看着有点乱」，同类屏「很美观」。实测对比后定四条，**这是排版及格线，不是加分项**：

1. **一屏一个绝对主角，字号断层要狠**：实测 100ha 屏＝主角 110px vs 其余全部 20-24px（**比例 5:1**），中间档为零。反面（我们 S03）：「长连接」108px 旁边杵着「Codex 坏了?」64px＝两个大字争重心，读者不知看哪。**一屏只允许一个 ≥64px 的字**，第二主角必须降到 24px 档或退场。
2. **形态多样＝天然分组，全文字行必糊**：100ha 屏 14 个信息点只用了 **4 个视觉对象**（超大数字/对比条组/chips 行/次级数字），非文字形态占 3 种，信息自动分块；我们同类屏 14 个信息点＝ **14 个文字行**，只能靠字号颜色区分，糊成一片。**一屏至少 2 种非文字形态**（图形/带框 chips/条/卡）。
3. **同一视觉符号一屏 ≤2 次**：竖条 kicker 参考侧一屏 2 个（THE FARM / FARM MANAGER），我们 3 个（DIAGNOSIS/CONNECTION/PROTOCOL）＝符号用滥、失去分节意义；独立成行的灰 EN caps 参考侧 2 处、我们 4 处。**竖条 ≤2、独立 caps 行 ≤2、同款图标行 ≤2**。
4. **信息递进不平铺**：结构是「主角数字 → 换算类比 → 同类对比 → 明细 chips → 下一层 kicker+次级数字」，每层角色不同、互为支撑；我们是「判定/连接机制/状态/协议/概念」五个**平级小块**堆叠，没有主从。**排版前先问：这些块谁是主角、谁在支撑主角？支撑不了的合并或删。**

**推论（推翻旧口径）**：rhythm 规则 2.5「≥4 异质层」的「层」指**视觉对象**不是文字行——**用图形压缩信息、减少视觉对象数量**才是丰富，堆文字行是反面。层数指标与本条冲突时以本条为准。

### 7.7 字阶空档带：5 档 + 禁落中间值（2026-07-25 逐帧实测，本条优先于规则 8 的一般表述）

实测参考片全片字号只有 **5 档**，且**档与档之间留有空档带，全片没有一个字号落在空档带里**——这是层级不糊的物理原因（我们之前塞满中间尺寸，是「排版乱」的根因之一）。

| 档 | %画高 | 1080p px | 用途 |
|---|---|---|---|
| T1 主角 | 9.8-12.8% | 106-138 | 大数字 / 大名 / 唯一主角 |
| **空档带** | — | **91-105** | **禁用** |
| T2 | 4.7-6.6% | 51-71 | 单位 / 字幕 |
| **空档带** | — | **43-50** | **禁用** |
| T3 | 3.0-3.9% | 32-42 | 小标题 / 清单条目 |
| **空档带** | — | **26-31** | **禁用** |
| T4 | 1.6-2.3% | 17-25 | 眉头 / 胶囊 / 注脚 |
| **空档带** | — | **13-16** | **禁用** |
| T5 | 0.9-1.1% | 10-12 | 英文注脚 |

- **相邻档比值 ≈1.8×**（近似等比阶）；**最大:最小 = 13.8:1**（同为中文时 5.9:1）。
- **一屏一个 T1，且 T1 与第二大元素至少差 1.5×**（实测 1.5-3.3×，中位 2.0×）。
- **主角三不**：永不带底板、永不带图标、永远享有最大留白（跨级留白 ≥130px@2160 ≈ 65px@1080）。
- **同级元素平级做法**：字高 **±1px**、左缘 **±2px**、行距锁死**单一值**、形态完全复制；**差异只允许出现在「颜色」一个维度**。
- **编码分工**：层级只靠**字号+明度+位置**；**色相只编码语义、不编码层级**；字重只做二分（T1-T3 Bold/Black，T4-T5 Medium）。

### 8. 字号只允许 SIZE 阶梯内取值

- 全部文字取 tokens.ts 的 SIZE 阶梯档位，禁止阶梯外字号、禁止对 token 做硬乘系数（裁决 4 的教训：BilingualSub 乘 1.13/1.17 造出阶梯外字号，已回收）。
- 比例关系可以写进装配决策（如规则 1 的「≥ 3 倍」），具体像素永远查 tokens.ts。
