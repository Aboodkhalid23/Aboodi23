# 版式构图（layout）

来源：assembly/0715-01/深度对比报告.md「版式构图与空间利用」8 条 + 查漏 2 条；修改单-04 对抗审查勘误·裁决 3（takeover 机制以裁决为准）；remotion-assembly SKILL §1 三区版式（全文搬入，此处为真源）。

## 适用时机

装配流程第 2 步「产出装配方案表」时逐 beat 读：给每个 beat 标主区（左/右/takeover）、选左区编组模板、判定素材是否升级 takeover。装配后验收时按本文件逐条截帧检查（叠字、越界、骑线）。

## 规则

### 1. 三区版式基线（搬自 assembly SKILL §1，此处为唯一版本）

构图先行：信息区放哪边——**问用户，别自作主张**。抽 3-4 帧看人物位置，但最终以用户裁定为准（0715-01 教训：人物居中偏左、右侧白板留白，AI 自作主张镜像到右侧被纠正——用户要的就是基准片原版左侧信息区，站位就是给左边留的）。作者默认：**信息 MG 放左侧**，容器 `left:0; width:640`、内容锚 `left:72`、右缘 ≤640；SideLabel 默认左上；字幕底部居中。

- **左区 x 72-640（＝画宽 3.75-33%）**：常驻 HUD——侧标、大字标题、TypeLockup、chips、Checklist、小型数据组件。scrim 只垫这一侧（scrim 具体规格见 texture.md）。
- **⚠ 分区口径升级（2026-07-25 八维实测，覆盖旧「人物区 x700-1150」矩形口径）**：真正的禁区不是一个竖条矩形，而是**人脸盒**——实测 `x 45-62% × y 23-56%`（人脸中轴均值 52.5%、发顶最小 23%、下巴最大 55.5%，三片交叉验证离散度仅 1.2%）。**眼/嘴/额头被压次数 = 0**。人脸盒之外的人体（脖/肩/胸/臂/手）**可被细线穿过**：躯干带 `y 50-80%` 是黑衣零细节区，压细线不损失信息。完整分区见 §1.7。
- **文字块右界 ≤ 画宽 45%**（实测极值 42.2%）：**过中线的只能是「几何量」**（条/线/轴），且其文字标签仍须留在 ≤35%，只有数值紧贴条尾。判据见 §1.6。
- **右区 x 1150-1848＝真素材证据位（2026-07-25 修正， 0723 全片 36 帧验证）**：只放**真素材**——真截图卡、真照片、产品图、B-roll 卡。这类素材是主角要放大展示，禁止龟缩在左区（用户 v1 反馈）。**右区禁放文字信息组**（状态标/脚注/清单/kicker/大字/印章等）——全片右侧只有「真素材卡」与「空」两种状态，文字组出现次数为 0；把文字甩到右侧是 0724-01 S03 两次翻车的根因。
- 字幕单条 ≤16 字（长句按标点拆条、时间按字符占比分），超长字幕两行起就是错。
- scrim 层级：视频层之上、所有 Scene 之下。

### 1.55 MG 是「从左边缘生长的系统」，不是左右两栏（2026-07-25 用户裁定 + 0723 全片验证）

**这是版式的总纲，优先级高于本节其余空间条款。** 我们长期把版式理解成「左信息栏 / 人物 / 右信息栏」两栏对称，实测参考片不是这个结构：

- **一切文字类 MG 从左边缘 x72 起排**——kicker、大字 hero、chips、清单、状态标、脚注、流程链、时间轴、对比条，无一例外，起点永远在左。
- **向右延伸多远由内容决定**：短件止于左区（x≤640）；横向结构件（§1.6 三类）可一路延伸横贯中区乃至抵达右侧，延伸是「长出来的」不是「摆过去的」。
- **右侧不是第二个信息栏，是证据位**：只接真素材卡（见规则 1 右区条），没有素材时**就让它空着**——空是正常状态，不是待填的坑。
- 判据自检：这段的文字件是否都能从左边缘一路读下来？有没有哪个文字组是「孤零零起在右边」的？后者一律搬回左栈。

### 1.6 中区横贯：判据是「信息是不是横向结构」，不是「有没有空位」（用户裁定 2026-07-25， 0723 片六例实证）

**只有三类信息可以横贯人物区**——它们的语义本身就是横向展开，挤到一侧就读不出来，所以横贯是**内容要求不是设计选择**：

| 类型 | 语义 | 实证 |
|---|---|---|
| **时间轴** | 从 A 时间到 B 时间的跨度 / 演进顺序 | 2:50「MAY 14 ——8 DAYS—— MAY 22」；3:55「入门→百本练习→落地系统→Agent 迭代」 |
| **流程链** | A→B→C 的先后顺序 | 1:38「LINE 发指令→Workers 存→ESP32 轮询→驱动电机」；2:27「手机点一下→哪块地干了多久→自动进数据库」 |
| **对比条** | 谁长谁短的量级对比 | 2:00「自己做 十几万円 vs 外包 ≥100万円」；4:12「想象力/用途 不够丰富·也不够多」 |

（连接关系 rig「A ⇄ B」按同理归入，它是流程链的二节点特例。）

**形态硬线（六例 100% 一致）**：
- **细线/细条 + 节点/小标签**，视觉重量极轻——人物照常看得清，不是「盖住半张脸的大图形」；
- 走**画面中段偏下**（人物胸口/手部高度），**六例无一压脸**；
- **逐节点长出**跟着口播，长完常驻 5-8s，不是闪一下。

**块状元素一律留两侧，无例外**：大字 hero、大数字、卡片、chips、真截图卡、印章、状态标签（UNSTABLE/RETRY 这类）——六例中块状件跨中区次数为 0。**把块状标签甩进中区是 0724-01 S03 右侧排版翻车的直接原因。**

**反面纪律（AI 高发错误，2026-07-25 实锤两次）**：
① 禁「为了用上中区去找地方占」——先看这段有没有上表三类信息，没有就不跨，中区空着是正常状态；
② 禁为凑中区**新造冗余信息**（S01 曾在「重连次数」已有点阵+计数两处表达后，再加一条断连脉冲线＝纯凑数，被用户否决）。

### 1.7 实测分区表与横贯元素落位公式（2026-07-25 八维拆解，本节数值优先于本文件其余像素口径）

**分区（画面百分比，1920×1080 下的 px 见括号）**

| 区 | 范围 | 性质 | 判据来源 |
|---|---|---|---|
| 死区 | x 0-4%（0-77） | 任何元素不入 | 实测无元素 |
| **左基准线** | x **4%**（77） | 所有文字件左缘对齐于此 | 全片唯一硬锚，kicker 竖条/hero 首字/chips 首框/图表首标签/脚注首字全对齐 |
| 主信息柱 | x 4-45%（77-864） | 11 类元素中 9 类住这里 | 右界实测极值 42.2% |
| 缓冲带 | x 45-55%（864-1056） | 只有几何量可侵入 | 非阅读性元素 |
| **人脸禁区** | x 45-62% × y 23-56%（864-1190 × 248-605） | **绝对禁区** | 眼/嘴/额头被压 0 次 |
| 躯干横穿带 | y 50-80%（540-864） | 细线/细条可穿 | 黑衣零细节区 |
| 头顶横带 | y 0-23%（0-248） | **唯一可跨中轴的整块通道** | 人体在此高度不存在 |
| 人像与证据带 | x 55-96%（1056-1843） | **只放真素材，从不放自制文字** | §1.55 |
| 字幕带 | y 86-100%（929-1080） | 工程硬约束 | 渲染器固定输出 |

**纵向五横带**：7-15% 路标 → 19-43% 主标 → 44-68% 论据 → 72-80% 结论 → 87-99% 字幕。**新元素只往下长**，从不插队、从不横向另起一列。

**横贯元素落位公式（核心，13 实例无一例外）**

> **y = C + 0.70·H**（C = 下巴 y，H = 头高 = 下巴 y − 头顶 y）
> 允许范围 `C + (0.65 ~ 1.05)·H`，绝对值落在画高 **63-72%**，即胸口到交叠的手那一带。

- 元素本身有高度时，取其**视觉重心**代入。
- 落在脸带 `[T, C]` 内的元素**一律不得横向越过人物轮廓**，靠「在轮廓前截断」存活（宁可截断文字也不越线）。
- 头顶带 `y ≤ T − 0.05·H` 放章节标签与 chips 行。
- **紧贴时安全间距 = 画宽 1.5-2%**（1080p 下 29-38px）——是「贴着轮廓收住」不是「离远点」。
- **撞上人物时不移动元素**，而是降到 ~20% 不透明度或羽化淡出；通道按机位**一次定**，不逐帧碰撞检测。
- **反面（0724-01 实锤）**：我们把连线放在 y=48%，而下巴在 53%——线落在脸带内、糊住嘴，被用户判「一定要往屏幕中间凑」。差的不是几像素，是差了一个身体部位。

**⚠ 景别修正（2026-07-25 0724-01 实测补，与上式配套使用）**

`C + 0.70·H` 是**中景**（脸占屏约 2.1%、发顶 y23-31%）下的取值，其物理含义是**胸口带**。景别变了倍数就不成立——0724-01 是**近景**（发顶 y≈6%、脸大得多），套同一公式算出 893px 会直接撞进字幕带。

> **公式的本质是「部位锚定」，不是头高倍数。** 先按部位定带，再用倍数当校验。

**两步定位法（每片开工必做）**：

1. **抽 3-5 帧画刻度线目视实测**六个锚点：发顶 T / 眼 / 嘴 / 下巴 C / 领口 / 字幕净空线。（自动肤色分割在暖调背景片上会整屏误判，实测踩过——用刻度线目视更可靠。）
2. **可用横穿带 = 领口下沿 ~ 字幕净空线**，再扣掉该组自身高度（节点标签等），取中段落位。
   - 中景（发顶 y≥20%）：结果通常 ≈ `C + 0.70H`，两法互相印证；
   - 近景（发顶 y<15%）：以部位为准，头高倍数会算飞。

**0724-01 实测样例**（1080p 近景）：眼 310 / 嘴 490-510 / 下巴 550 / 领口 600 / 手 600-750 / 字幕净空 840 → 可用带 600-840，扣组高 160 → **连线落 y680**。旧值 520 正压下唇＝用户判「糊嘴」的直接原因；按头高倍数算得 893＝撞字幕带。**两个错误方向都验证过，取中段部位锚定才对。**

**禁止套用别片的绝对像素**，也禁止跨景别套用头高倍数。

### 2. takeover 两级机制（裁决 3 全文，覆盖报告中四种口径）

- **A 级「素材接管」**：人物整段退场（**用户 2026-07-16 否决 PiP 小窗，覆盖旧裁决——接管一律不带 PiP**），时长 8-15s，每个 case 一次，素材卡宽 ≥1100px。适用：引用/推文、产品演示、B-roll 三类星级素材，默认走 A 级而不是塞右区。dark 接管底用半透暗幕 rgba(6,7,10,0.88)（人物隐约可透，基准片渐进接管手法），light 用实底 #F2EFE9 + 左缘压暗带保侧标可读。
- **B 级「压暗升格」：已被用户否决**（2026-07-16：「我的画面不是很暗的，不用加什么暗暗的特效」）。升格时刻（VS 决算/全片级判词）改靠版式本身：字号提级 + 清场 + 红绿镜像框，禁止 DimStage 全帧压暗。
- **接管频次（2026-07-20 降级为可选，覆盖旧硬性默认）**：原「A 级素材接管每 60-90s 至少一次」从硬性默认降为**可选手法**，不再作硬性节拍指标——只在真正必要处用（见下条终审裁定），优先级低于该裁定。
- **默认接管翻转·终审裁定（用户 2026-07-20，优先级高于本节其余 A 级接管规则）**：默认人物全程在场 + MG 两侧叠加（三分版式：**信息左 x72-640 / 人物中 x700-1150 透出 / 证据右 x1150-1848**，对标原片全程如此，从不整屏变黑）；引用/背书类默认右区卡 + 人物在场。**A 级全屏黑接管（Takeover dark）只在真正必要时用**——如切入 B-roll 素材、需整屏腾空间的关键峰值（case study 峰值素材）——不作为默认、不滥用。滥用全屏黑已被用户否决（黑太久、像剪辑失误、单调）。原「A 级接管每 60-90s 至少一次」由此从硬性默认降为可选手法。dark 接管底必须半透暗幕（人物隐约可透），**禁实底全黑**；暗幕随卡同退，禁在卡退场后常驻空挂（0715-02 S04 事故：卡退场暗幕常驻，画面偏暗偏空被终审打回）。**片尾不黑（0715-02 终审）**：CTA/收尾段同样默认人物在场收尾，禁以长黑场/全屏暗底收尾——与滥用全屏黑同罪。
- **A-roll 常驻铁律·终审裁定（用户 2026-07-22，优先级高于本节其余全部接管规则，覆盖 2026-07-20 裁定的模糊处）**：**只有整屏 B-roll 环节才允许人物从画面消失；但凡不是整屏 B-roll，A-roll 一律常驻不切**（用户原话：「只有放全屏的 B-roll 的环节才需要让我的人物从画面里消失，但凡不是放全屏的 B-roll 的，都不要让我的 A-roll 从画面里消失」，参照剪辑）。推论三条：① **纯 MG 峰值拍禁切人物**——rhythm §2「每章一次 2-4s 整屏峰值插拍」中的「整屏」自此解释为「MG 满编占满信息区」，不解释为「切走人物」，禁以峰谷落差为由插纯 MG 满屏拍（0722-01 judge 曾据旧口径打回节拍维，经此裁定撤销）；② 手绘氛围场/模拟卡**不算 B-roll**，不构成切人物的理由——素材缺位时降级手绘的段落应保持人物在场、手绘场作左区或半屏叠加；③ 判词升格、章级重锤、概念定义、后果清算等高光时刻，靠字号提级+左区清场+语义色实现量级，不靠切人物；④ **B-roll 默认走右区卡片承载（非整屏）**——素材放三区版式右区证据卡、16:9 等比不裁切、人物常驻、左区留侧标+时间线 HUD（0722-01 定，承载件见 `src/koubo/scenes-0722-01/CollageBroll.tsx`）；整屏接管只在「无信息需与素材并置」时才用，是本铁律唯一允许人物消失的场合。别把 B-roll 默认做成整屏（0722-01 误做整屏被用户否决重来）。执行细则见 remotion-broll SKILL「AI 生成拼贴 B-roll」节。
- **z 序**：takeover 层在 video 之上、SideLabel 与字幕之下；SideLabel 从 Scene 内提升到顶层常驻（白底接管时 SideLabel 用 surface 适配）。
- **MG 提层（2026-07-24 立项，工程底座待建）**：词级精读证实其 MG 层完全独立于剪辑层（hero/清单/图表跨镜头硬切零位移常驻 8-23s）。我们现行「每段一个 Scene、Sequence 边界即卸载」使跨段常驻只能靠相邻 Scene 重复实现（0724-01 侧标每段重渲进场闪一次即此病）。目标形态：**跨段常驻元素挂主组件级顶层轨（同 SideLabel/字幕轨），Scene 只管段内元素**；配套喂养驻留制（rhythm 规则 4）。下一片装配时建此底座，建成前用「相邻 Sequence 重叠 + 同参数续渲」过渡。
- **左栈四态模板（ segA）**：同一竖栈骨架（kicker→眉标→主体→副行）四种主体互换——图标清单态/hero+图表态/hero+卫星态/引语卡态；换态只换中间主体，骨架与锚位不动，形成节目识别度。
- A 级主证据卡宽 ≥1100px、占画面 ≥60%。

### 2.5 素材排版三档：按素材占屏比例选构图（2026-07-21 基准片 B-roll 片实测定档）

素材段不是「全屏或右区卡」二选一，是三档连续谱（实测证据：previews/broll-study/，57-68s 与 99-107s 帧）：

- **A 全屏（100%）**：场景铺底（broll 规则 9，MG 左栈叠加）或操作演示接管（broll 规则 6，左带 HUD 留守）。素材是唯一主角、需要连续自我演示时用。
- **B 偏置接管（素材 ~70-75% 右 + 左带 ~25-30% 叙事带）**：人物退场；左带深色底＝侧标（顶部）+ 步骤/要点 chip 栈纵排**跟口播逐项点亮**。**竖向/长条内容（网页、文档、聊天流）选这档**——卡收窄留左带，素材与论点双线并行（实测 57-68s：知识库四步 chip 栈）。
- **C 半屏共存（素材 ~50-55% 右 + 人物在场左 1/3）**：口播主导、素材是配图证据时用——人不退场保讲述连续性，左下配功能/概念 lockup 点题（实测 99-107s：双语字幕演示卡+lockup）。**前提＝人物构图在左 1/3**：4K 粗剪二次构图裁切实现（人物位移伴随素材切换发生，位移即切镜、禁缓慢漂移）；1080p 源无裁切余量时本档不可用，回退 A/B 或右区标准卡。
- 选档判据链：素材要连续演示自己→A/B（竖向内容→B）；口播主导素材配图→C；素材只是佐证一句话→右区标准卡（规则 4）。
- 美观细则（三档通用）：素材一律圆角卡装框+阴影、四周留边不贴死边、底部留字幕净空；同段卡样式统一；B 档左带与 C 档 lockup 是「素材段的 MG 叙事线」，不许素材独角戏超 8s 无 MG 增量。
- **选档判据补充（2026-07-21 0721-01 八段对照原片复盘定，五处降档实锤）**：① 原片该处人物离场＝A 档强信号，勿退成人物在场纯 MG（S01 hook 原片全屏铺底+人物离场 9s 被退成纯 MG，冲击力降级）；② 同源素材跨相邻段连续使用时，接管窗按**跨段合并时长**判档，禁按单段孤立时长降档（S02 按单段 3.7s 判「不足接管窗」降小卡，原片实为跨两段 6.7s 全屏接管）；③ 原片贴边出血近全屏的，我方 ≥85% 屏宽或同样出血，禁缩成中卡（S10 缩成 67% 中卡偏小）；④ 素材段整窗禁空窗：素材时长不足时在源内找第二相位续窗（原片语法），禁收卡后半屏裸空（S16 收卡后右半屏裸空 5.4s）；⑤ 全屏虚化素材当底纹+MG 压上是合法档位——全虚素材装进卡框会读作「素材糊了」（S14）。占位/自备素材的 MANIFEST 建议档只是初值，装配时仍按本判据链定档。

### 3. A 级接管不带 PiP（用户否决，覆盖查漏条 1 与裁决 3）

基准片原片确有右上 PiP 谈话头，但用户 2026-07-16 明确否决「人物缩小到右上角」——我们的接管人物整段退场，靠 dark 半透暗幕让人物隐约可透来保持「人还在」的连续感（seg01 已按此过审）。此为用户裁定，优先级高于参考片复刻。

### 4. 右区卡吃满全宽，禁止越界，无中间态（sev4）

- 留在右区的卡片：左缘 = x1150、宽约 680-698（吃满 x1150-1848），高度可放到画面 55-60%，文字随卡等比放大。
- 禁止为塞大卡越过 x1150 侵入人物区。
- 卡片需要 >698px 宽时：4K 源可二次构图的片走规则 2.5 C 档（人物裁至左 1/3、卡可到 ~55% 屏宽——2026-07-21 实测勘误，中间态在此前提下合法）；1080p 源无裁切余量时维持旧规升 A 级接管，不允许中间态。

### 5. 右区先标定「白板安全框」，禁止元素骑亮暗分界线（查漏条 3）

右区有实体亮面（白板）时，装配层先按实拍白板内沿标定安全框常量（0715-01 约 x1200-1830 / y90-940，每片实测）：单个元素必须整体落在框内或整体落在暗墙区，禁止骑线；同组元素必须同底。

### 6. 左区编组模板：海报不是列表（sev4）

左区每屏必须有一个尺寸 ≥2.5 倍于其他元素的视觉锚点；连续等宽等距堆叠不得超过 3 个，超过就改用编组模板。三个模板：

- **A「大数字锚点 + 卫星元素」**：BigNumber 锚点 → 条形对比 → 图标流程，三级结构，锚点与最小元素尺寸对比约 3:1。
- **B「图标网格 + 右侧吸附卡」**：mini 卡吸附在图标网格右侧成两栏。
- **C「容器卡内嵌芯片组」**：带描边容器大卡把芯片编成一组。
- **三模板选择判据**：数字/单主角主导 → A；图标组/多小件主导 → B；同类芯片 ≥4 颗 → C（与 rhythm 规则 5 pill 上限联动）。

### 7. 一屏一个主重心（sev3）

装配时给每个 beat 标记主区（左/右/takeover）；主区之外的另一区同屏最多保留 2 个芯片/图章级小元素，信息卡与流程图等卡片/图表级区块不得双区并存。

### 7.5 章结论级 h1 lockup 是导航不是主角：新主角进场即 dim（seg02 过审沉淀）

- **章结论级 h1 lockup（两档制上档，须 dim 让位）**常驻期间，当句主角元素（证据卡/大数字）进场时它必须 dim 到 0.4 让位（DimAfter 门控，12 帧过渡）；唯一最大亮度永远属于当句信息。
- 两档制辨析：**章节常驻导航牌（72 档）常驻不 dim**（见 typography.md 规则 2 / specs.md §3），本条 dim 让位只针对章结论级 h1 lockup，别把两档混为一谈。
- 反面：v4 标题全亮常驻到章尾，73% mega 进场后画面双红巨字争重心。

### 8. 章节 hero 独占进场（sev3，版式部分）

章节 hero 进场的 2-3s 内左区其他小元素延后进场，hero 同屏不得出现第三个文字元素；hero 是该屏唯一重心，配同尺度 icon。hero 用 SIZE.h1（裁决 2：h1 已提级，章节 hero 用 h1 是义务，不允许降级 h2）；字号阶梯细则见 typography.md。

### 9. 左上标头区互斥占位（sev4，实际渲染事故）

左上标头区（SideLabel 锚点下两行）同一时刻只允许一个占位者：问题眉线出现期间替换第二行小注而非叠加；同一 y±24px 内只允许一个文字元素。新元素进入必须先让旧元素退出。装配后逐段截帧检查左上角无叠字。

### 10. 咬合位：主从元素成对咬合，反平铺（sev2）

主卡 + 卫星芯片成对出现时，卫星默认旋转 -10°~-6° 压主卡角 12-20px，制造主从层次；仅用于主从关系明确的元素对，单屏咬合不超过 2 处。

### 10.5 纵向占位表：写码前先排表，防重叠的根本手段（2026-07-16 用户点名 MG 防重叠不达标后定）

重叠不是渲后查出来的，是写码前排掉的。每段动工时先给左区（及右区多元素时）列**纵向占位表**：每个元素一行 `top..bottom`（含入退场时段），例：`标题 150-320 / kicker 352 / waffle 392-548 / mega 数字 568-764 / chip 772-826`。硬约束：
- 相邻元素间隙 ≥12px；底线 ≤y840（字幕净空）；同一时段两行区间不得相交。
- 时间维度也查：A 退场前 B 进场且区间相交 = 重叠（服役区间要错开或让位）。
- **合法重叠只有一种**：规则 10 的咬合位（≤2 处/屏，且不得遮任何文字）。
- **null 门控：入场前不渲，防幽灵重叠**（2026-07-17 seg05/12/17/18 立案）。（**代号落点**：`Place` = 定位盒组件、`qcAllow` = 咬合位 QC 豁免 prop，均在 `src/koubo/scenes/shared.tsx`；`QcProbe` = 逐帧读 `[data-qc]` 盒判重叠的 QC 探针，在 `src/design/qc.tsx`，见错题 #29。）共享件在 enterAt 前虽 `opacity 0` 但仍渲一个满尺寸盒（`getBoundingClientRect` 照返回布局尺寸），外层 Place 盒 `opacity` 恒 1 → QcProbe 把这个隐形盒读成重叠（占位表查不出、渲后也看不见，是纯 QC 盲区）。共享件不可改（防多 Scene 撞车），故在**调用点**门控：`if (frame < enterAt) return null`（退场同理加 `|| ex.opacity<=0`），让 Place 盒塌到 0、不进 QC。判据：凡「入场前占位 / 退净后仍挂载」的共享件，调用点必须有 return null 门控；已在 S5Appear（S05）/整墙容器（S12）/决算框（S17）/S18 四处稳定运行。
- 表写进该段方案文档，验收时对表检查。

### 11. 版式验收清单（装配后逐项截帧核对）

按 beat 抽帧（每章至少中段 1 帧 + 每个 takeover 段 1 帧），逐项过：

1. A 级 takeover 是否只出现在真正必要处（B-roll/case study 峰值），无为凑频次的滥用全屏黑？（2026-07-20 裁定：不再要求每 60-90s 一次，接管改为可选，见规则 2）引用/演示/B-roll 若确要接管是否走了 A 级而不是塞右区？
2. A 级段：素材卡宽 ≥1100px、占画面 ≥60%？无 PiP 小窗（用户否决）？结束后人物淡回？
3. 右区卡左缘 = x1150、宽 ≤698？**中区占用按 §1.6 核**：跨中区的是否只有时间轴/流程链/对比条三类（细线细条+节点、走胸口高度不压脸）？块状件（大字/大数字/卡片/chips/印章/状态标签）是否全部留在左右两区？有无「为占而占」或新造冗余信息？
4. 右区元素是否整体落在白板安全框内或整体在暗墙区？同组元素是否同底？
5. 左区每屏有无 ≥2.5:1 的视觉锚点？有无 ≥4 个等宽等距纵列堆叠？
6. 每屏是否只有一个主区重心？非主区是否 ≤2 个芯片级小元素？
7. 左上标头区同一 y±24px 是否只有一个文字元素（重点查问题眉线出现段）？
8. hero 进场 2-3s 内左区是否干净？
9. 咬合位是否 ≤2 处/屏、仅用于主从元素对？
